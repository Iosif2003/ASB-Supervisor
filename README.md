    n# ASB-Supervisor

STM32F446RE firmware for the ASB (Autonomous System Brake) supervisor.
Aristurtle Formula Student.

## How the system works

The EBS has two independent pneumatic circuits. Each one has its own air
tank and solenoid valve and feeds one brake cylinder, so one leak or one
dead valve still leaves a working brake. The valves are fail-safe: with
no power they let the air through and the car brakes, the MCU has to keep
them powered to drive.

On circuit 1 there is also a proportional valve in parallel with the
solenoid valve, driven by the DAC. A shuttle valve passes whichever of
the two has the higher pressure to the cylinder. That is the service
brake (park / hold, and it is tested in the initial check).

The ASB also has a relay in the shutdown circuit (SDC) and an external
hardware watchdog. If the firmware stops sending watchdog pulses the
relay opens by itself.

## Code overview

Start reading from the main loop in Core/Src/main.c, then the modules
in this order:

| File | What it does |
|------|--------------|
| asb_config.h | all limits and timings (pressures, debounce, DAC values) |
| asb_initial_check.c | initial checkup state machine, runs in AS_Off |
| asb_monitoring.c | continuous monitoring, any failure -> EBS + SDC open |
| asb_ebs.c | the two EBS valves, EBS state for the APU |
| asb_service_brake.c | proportional valve through the DAC |
| asb_sensors.c | tank pressures from the ADC, brake pressure from CAN |
| asb_system.c | SDC relay, watchdog, digital inputs, mission, manual mode |
| asb_can.c | all CAN RX / TX |

Timing: everything runs from the main loop on flags set by timer
interrupts. 10ms (TIM4) for the logic, 20/50/100ms (TIM5/6/7) for the CAN
frames. TIM2 triggers the ADC every 10ms and TIM3 makes the watchdog pulse.

Generated files, don't edit by hand:

- can_mcu.c / can_mcu.h are generated with cantools from the CAN DBC.
  When the DBC changes, regenerate them.
- main.c, main.h, stm32f4xx_it.c, stm32f4xx_hal_msp.c are generated by
  CubeMX from ASB_Supervisor.ioc. Only write between the
  USER CODE BEGIN / END comments, the rest is overwritten on regeneration.

Pinout (see main.h):

| Signal | Pin |
|--------|-----|
| EBS valve 1 / 2 | PA5 / PA6 (low = braking) |
| Proportional valve (DAC OUT1) | PA4 |
| Tank pressure 1 / 2 (ADC) | PC5 / PB0 |
| AS relay signal (SDC) | PB13 |
| AS relay in / out | PC2 / PC1 |
| Watchdog pulse (TIM3 CH4) | PC9 |
| ASMS / TSMS | PC13 / PB9 |
| Interlock valve 1 / valve 2 / proportional | PA2 / PA1 / PA0 |
| Interlock steering | PC3 |
| CAN1 RX / TX | PA11 / PA12 |
| User LED | PB12 |

## Build

### CMake (terminal or VS Code)

Needs CMake 3.22+ and Ninja, both come with STM32CubeCLT.
The ARM toolchain is picked up automatically from CubeIDE / CubeCLT /
Arm GNU Toolchain installs, whichever is newer.

```
cmake --preset debug
cmake --build --preset debug
```

Output goes to build_cmake/ (ASB_Supervisor.elf and .bin).
There is also a release preset (-Os) that builds into build_release/.

If the toolchain is not found automatically point to it manually:

```
cmake --preset debug -DTOOLCHAIN_DIR="<path to the toolchain bin folder>"
```

In VS Code just pick the Debug preset when CMake Tools asks and build.

### STM32CubeIDE

Import as existing project and build like normal. Build folders are
gitignored.

## Flash

From CubeIDE with a debug session, or with the command line:

```
STM32_Programmer_CLI -c port=SWD -d build_cmake/ASB_Supervisor.bin 0x08000000 -rst
```

Copying the .bin onto the Nucleo USB drive also works.
